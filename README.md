# Computer Atlas

**English** | [简体中文](README.zh-CN.md)

An interactive computer anatomy tutorial built with React, Three.js, and Vite. Explore a desktop computer, take it apart, and follow how power, data, and heat move through its components.

The application runs in the browser without a backend, paid services, or API keys. English is the default language; Chinese is also supported.

## Quick Start

Install a current Node.js LTS release with npm, then run:

```sh
git clone https://github.com/qingfengzxr/computer-altas.git
cd computer-altas
npm install
npm run dev -- --port 5173
```

Open the local URL printed by Vite. If the port is occupied, use the URL Vite reports.

| Command | Purpose |
| --- | --- |
| `npm run dev` | Start the development server |
| `npm test` | Run automated tests |
| `npm run build` | Generate the production site in `dist/` |
| `npm run preview` | Preview the production build locally |

Deploy `dist/` to a static hosting service. For deployment under a URL subpath, configure Vite's `base` before building.

## Features

- **29 selectable components:** rotate, zoom, locate parts, inspect related hardware, and toggle labels or the side panel.
- **Flat disassembly:** at 100%, visible components spread into rows with relative sizes preserved. Return to 0% to reassemble.
- **Six system layers:** filter hardware and search by English name, Chinese name, or component ID.
- **Animated processes:** inspect power branches, a four-stage data flow, and separate heat-conduction and airflow stages. Pause, advance manually, or replay.
- **Three guided lessons:** progress through component selections and process observations.
- **Startup diagnosis:** restore standby power, press the case button, and observe initialization. Fans, the PSU rocker, and indicator lights reflect the power state.
- **Desktop and mobile layouts:** progress is stored in the current browser. Text learning remains available if WebGL fails.

## Language Support

Use the application's upper-right language menu to switch between English and Chinese. The preference is saved in the current browser without resetting the selected component, disassembly amount, lesson step, or diagnosis state.

Both languages cover component descriptions, model labels, lessons, diagnosis clues, process stages, and accessibility labels. Search accepts both Chinese and English names in either interface language.

To switch this repository's documentation, use the language links at the top of either README.

## Hardware Models and Accuracy

Geometry and PCB artwork are generated by project code. No commercial 3D model or vendor CAD asset is bundled. One scene unit represents 100 mm.

| Reference hardware | Modeled details |
| --- | --- |
| Noctua NH-L9i | Published 95 x 92 x 23 mm heatsink envelope, 37 mm total height with fan, 54 fins, and two 6 mm heat pipes |
| Noctua NF-A9x14 HS-PWM | Nominal 92 x 92 x 14 mm frame, 82.5 mm mounting-hole spacing, and nine swept blades |
| Kingston KVR26N19S8/8 | 133.35 x 31.25 mm outline, eight front-side DRAM packages, 288 contacts, and a through-key opening |

Referenced parts link to manufacturer specifications in the component panel. Published dimensions are checked against generated mesh bounds; undimensioned shapes, finishes, and small details remain approximations.

Generic hardware includes PCB traces, socket retention mechanisms, power connectors, cable bundles, and rear I/O. Video receptacles meet the graphics-card PCB and move with it during initial disassembly. USB-A and Ethernet openings use compact connector proportions, with eight contacts and a latch opening in the Ethernet jack.

**This is an educational model, not a complete 1:1 desktop replica or manufacturing CAD.** The motherboard, graphics card, CPU/socket, power supply, storage, and chassis are not tied to specific commercial models. The tutorial does not validate real-world assembly compatibility, electrical routing, or manufacturing tolerances.

See [model conventions and limitations](docs/MODEL.md) and [manufacturer references and measurement scope](docs/REFERENCES.md).

## Teaching and Accessibility

- Switching on AC restores standby power; the case button starts simulated initialization. The duration is illustrative, not measured POST time. The standby LED represents this teaching configuration, not every motherboard.
- Power paths are simplified branches. Data stages omit caches and concurrency. Thermal animations distinguish conduction from convection but are not fluid simulations.
- Lessons require completion of the relevant process stages. Hidden endpoints do not leave orphaned animated flows.
- Reduced-motion preferences disable fans, particles, and automatic rotation; static arrows and manual progression remain available.
- The scene renders on demand when idle. Component markers support keyboard selection, the information dialog manages focus, and mobile tool buttons have 44 x 44 px targets.
- Process explanations appear outside the 3D canvas to keep the model visible. Cables disappear beyond 35% disassembly to make individual parts easier to inspect.

## Verification

The current suite contains 23 automated tests covering dimensions, GPU connector fit, USB/Ethernet openings, contact counts, flat layouts, power transitions, process rules, and translations.

Browser checks have covered desktop and mobile layouts, nonblank WebGL output, component close-ups, automatic rotation, and 29 non-overlapping parts at full disassembly. These checks do not establish performance on every physical phone. The production build succeeds with an existing Vite large-chunk advisory.

## Assets and Dependencies

React, Three.js, Vite, and Lucide retain their respective licenses. The page optionally loads Noto Sans SC through Google Fonts and falls back to local fonts when unavailable. Hardware geometry requires no external 3D downloads.

To add an exact commercial configuration, use manufacturer drawings or appropriately licensed CAD/glTF assets while preserving component IDs and teaching relationships. The current application does not provide account synchronization across devices.
